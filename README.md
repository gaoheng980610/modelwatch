# ModelWatch

An independent, provenance-tracked index of AI model **capabilities, context limits, pricing
and lifecycle** — published as a static website, a free read-only JSON API, and (planned) a paid
change-monitoring feed.

This repo is the engine of the venture described in `../THESIS.md`. It is designed so that the
*only* things a human must supply are identity gates (domain, accounts, payments) — everything
else is produced here.

## Layout

```
data/
  schema.json     JSON Schema for a model record
  seed.json       hand-curated baseline (always loaded first)
  sources.json    adapter config (which sources to pull, and how)
  models.json     current dataset — regenerated by the collector
  history/        dated snapshots = the compounding asset
  changes/        append-only change log (one entry per collection run)
src/
  validate.py     stdlib validator - SHAPE (schema, enums, numeric ranges)
  audit.py        content audit - duplicates, dead rows, provenance coverage
  adapters.py     pure parsers + merge rules (no I/O, unit-tested)
  collector.py    seed -> live adapters -> merge -> snapshot
  monitor.py      diff two snapshots -> change feed
  alerts.py       turn the change log into alerts for a watchlist (the paid tier's logic)
  build_site.py   static site generator (stdlib only)
  check_links.py  verifies every internal link + sitemap URL resolves
  check_claims.py recomputes the figures rendered on the site, independently
clients/
  js/             npm client (dependency-free)
  py/             PyPI client (stdlib-only)
.github/
  workflows/      daily collect -> test -> validate -> build -> commit (starts at G0)
site/             generated output (do not edit by hand)
tests/            unittest suite + fixtures
```

## Run

```bash
python src/collector.py                  # collect from all available sourcespython src/monitor.py                    # diff the two latest snapshots -> change feed
python src/alerts.py --watch watchlist.example.json   # alerts for the models you depend on
python src/alerts.py --all --format slack             # text | json | email | slack | webhook
python src/validate.py                   # check record SHAPE
python src/audit.py                      # check record CONTENT (duplicates, coverage)
python src/build_site.py                 # regenerate site/
python src/check_links.py                # verify every internal link resolves
python src/check_claims.py               # verify rendered figures against the data
python -m unittest discover -s tests -v  # run the test suite
```

Preview locally:

```bash
cd site && python -m http.server 8765     # http://127.0.0.1:8765
```

**Credential-free by design.** The collector loads `seed.json` first, then merges live
adapters on top. An adapter whose env var is unset is skipped, never failed — so it runs
today with zero accounts and upgrades itself the moment a key appears (e.g. set
`ANTHROPIC_API_KEY` and the official Models API adapter starts contributing real-time
capability and context-window facts).

## Deploy

Launch is configuration, not a code change:

- set `MODELWATCH_BASE_URL` (no trailing slash) — it drives canonical URLs, OG tags and `sitemap.xml`.
  Verified by building with a custom origin and confirming both followed it.
- the build also emits `_headers` (immutable cache for `/assets/*`, 1h for `/api/v1/*`, `nosniff`
  and a referrer policy) for hosts that read it — Cloudflare Pages and Netlify both do.
- host the generated `site/` directory on any static host.

The ordered, copy-pasteable go-live checklist is in **`LAUNCH.md`**; drafts of the announcement
posts (and the objections they need to answer honestly) are in **`docs/LAUNCH_POSTS.md`**.

## Output

- `site/index.html` — all models (filter by name/provider/price/context/vision/open-weights, sort by
  name, price, context or intelligence index)
- `site/new.html` — models released in the last 90 days
- `site/pricing.html` — pricing comparison + chart
- `site/providers.html` / `site/providers/<slug>.html` — provider index and per-provider pages
- `site/models/<id>.html` — per-model page (the SEO/asset unit, with JSON-LD + provenance)
- `site/compare/<a>-vs-<b>.html` — per-vendor pairwise comparisons
- `site/trends.html` — release cadence + dated change history
- `site/report.html` — original analysis computed from the dataset (context growth, multimodal
  adoption, price distribution), with the method and its caveats stated on the page
- `site/leaderboard.html` — models ranked by third-party intelligence index, with the input price
  per index point computed from the dataset
- `site/docs.html` — how to consume the API and read the confidence model
- `site/api/v1/models.json`, `site/api/v1/changes.json` — the free read-only API
- `site/api/v1/history.json` — the full append-only change log
- `site/feed.xml` — Atom feed of newly released models
- `site/sitemap.xml`, `site/robots.txt`
- `site/404.html` — branded not-found page with a search box (`noindex`; hosts serve it automatically)
- `site/_headers` — cache + security headers for hosts that read them

## Design

One design system in `src/build_site.py` (the `CSS` constant + the small component helpers):

- **Light and dark are both selected**, not auto-flipped — both columns come from one palette that
  passes `validate_palette.js` (lightness band, chroma floor, CVD separation, normal-vision floor,
  contrast) in each mode. A theme toggle persists to `localStorage`.
- **Charts are single-series horizontal bars** with the value at each bar's tip, a uniform scale cap
  so labels always fit, and a real table beneath every chart — so nothing is gated behind color.
- **Status is never color alone** — badges pair a dot with a text label.
- **Links have their own token** (`--link`), distinct from the chart series color, because the series
  blue does not clear WCAG 4.5:1 as body text; in-paragraph links are underlined so they never rely
  on colour alone. Verified with Lighthouse across every page type — Accessibility, Best Practices,
  SEO and Agentic Browsing all 100, light and dark.
- **The table is server-rendered in full**; the filter/sort script only hides and reorders rows that
  are already in the DOM, so crawlers still see every model.

## Data integrity rules (enforced)

1. **Every figure carries provenance** — a source URL, source type, and retrieval date.
2. **Every record carries an `as_of`** — a record is only as good as its as-of date.
3. **No guessed numbers.** Unknown values are `null`, never invented. Confidence is explicit
   (`verified` / `partly_verified` / `unverified` / `estimated`).
4. **Confidence-aware merge** — a third-party source can never overwrite a first-party
   `verified` figure; it may only fill gaps.
5. **A price object comes from exactly one source.** Sources that disagree are surfaced in
   `conflicts[]` rather than silently mixed or averaged.
